# Machine-specific configuration (`lab.conf`)

Goal: install the lab on any machine without changing the scripts. **`lab.conf` is the only file to adapt** (full
procedure: [installation.md](installation.md)).
Three categories of files are kept apart:

| Category | Examples | In git? |
|---|---|---|
| Code (the same everywhere) | `lab`, `scripts/`, `*.sh`, compose files, `docs/` | yes |
| Machine configuration | `lab.conf`, `windows/ssh_config_aibeast.txt` (generated by `lab client`) | no (`lab.conf.example`, `windows/ssh_config_aibeast.example` yes) |
| Secrets and data | `**/.env`, `client_secret*`, keys, `hermes/data/`, `bench/results/` | never |

## Setup

    cp lab.conf.example lab.conf
    nano lab.conf

`lab.conf` is read by bash: only `NAME=value` lines, without spaces around the `=`.
No password or key in this file: secrets stay in the `.env` files.
Without `lab.conf`, the default values apply.

## Variables

| Variable | Default | Used by |
|---|---|---|
| `LAB_DATA_DIR` | `/data` | `lab status`, `lab doctor`, `scripts/backup.sh` (restic repository, staging area, systemd unit), `8-stockage.sh` |
| `LAB_MODEL` | none | `lab` (takes priority over `lab config set MODEL`), `3-demarrer.sh` without an argument, `n8n/build.py` |
| `LAB_HOST` | none (required for `lab client`) | `lab client`: address of the AI machine as seen from your PC (local IP, VPN IP, Tailscale name) |
| `LAB_USER` | the user running `lab client` | `lab client`: Linux account for SSH |
| `LAB_SSH_PORT` | `22` | `lab client` |
| `LAB_SSH_KEY` | `~/.ssh/id_ed25519` | `lab client`: private key **on the PC** |
| `LAB_RDP_LOCAL_PORT` | `13389` | `lab client`: local port of the tunnel to the remote desktop (port 3389 of the AI machine) |
| `LAB_AGENT_SSH_ALLOW` | empty (no exception) | `lab isolation`: test machines Hermes may reach over SSH (`IP` or `IP:PORT`, separated by spaces) |

Notes:

- The `DataDiskAlmostFull` alert (Prometheus) and the "Data disk" tile of the portal watch every ext4, xfs or btrfs disk
  except `/`: they do not depend on `LAB_DATA_DIR`.
- Single-disk machine: set `LAB_DATA_DIR` to a folder on the system disk; `lab doctor` then shows a remark (`!`) instead
  of an error.
- The Windows scripts have no hard-coded path: the archive and the backup copy are looked for next to the `windows\`
  folder, and the location of the restic repository is asked from the AI machine (`lab backup repo`).
- `BACKUP_REPO` and `BACKUP_STAGE` still take priority over `LAB_DATA_DIR` for backups.
- An already installed backup timer keeps its systemd file. After changing `LAB_DATA_DIR`, run `lab backup schedule`
  again to rewrite it.
- `n8n/build.py` reads the environment variable, not `lab.conf`:
  `cd n8n && LAB_MODEL=name:tag python3 build.py`. Without the variable: `qwen3.8:27b`.
  Every run changes the random identifiers in the JSON files (noisy git diff, no effect).

## Fixed values (the same on every installation)

- The name of the SSH shortcut, `aibeast`, used by every script in `windows/`.
- The ports of the interfaces (all on `127.0.0.1`): changing a port means editing the compose file concerned and the
  list of tunnels in `scripts/client-config.sh`.
- The project folder is not imposed, but the Windows scripts assume `lab install` was done (`~/.local/bin/lab`).

## Git

The project folder is a git repository. The public repository was published with a fresh history, without the personal
values of the original machine.
Before any `git add`, check that no secret is being added:

    git add -n . | grep -iE "\.env$|secret|\.key|\.pem|/id_"
    git check-ignore -v ai-stack/.env lab.conf

Revert a file: `git checkout -- FILE`. History: `git log --oneline`.

## What is not verified

- A real `lab.conf` with `LAB_DATA_DIR` other than `/data` (only a temporary `LAB_DATA_DIR=/tmp lab doctor` test was
  done).
- `3-demarrer.sh` without an argument with `LAB_MODEL` set (not run: it restarts the stack).
- The rewrite of the systemd unit by `lab backup schedule` with another `LAB_DATA_DIR`.
- A full installation on another machine.
