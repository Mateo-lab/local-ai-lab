# n8n: sorting Gmail messages with the local model

Inspired by the "Gmail AI Email Manager" template (n8n.io, workflow 4722), adapted to this lab: each message is
classified by **Ollama, locally** (nothing goes to an AI provider). The workflows add **labels**; the only destructive
action, moving to the trash, is separate, manual and reversible.

## The four workflows (`n8n/` folder)

| File | Role | Runs |
|---|---|---|
| `gmail-create-labels.json` | Creates the 9 labels in Gmail | once, by hand |
| `gmail-sort-new.json` | Classifies **new** messages | automatically, every 5 min |
| `gmail-sort-old.json` | Classifies **old** messages, 200 per run | automatically at 1 am, or by hand |
| `gmail-trash-approved.json` | Moves the messages **you** approved to the trash | by hand |

The JSON files are generated by `n8n/build.py` (`python3 n8n/build.py` from the `n8n/` folder): edit the script, not the
JSON, to change a label, a category or the prompt.

## The labels

| Category | Gmail label |
|---|---|
| To answer | `AI/To answer` |
| Info | `AI/Info` |
| Notification | `AI/Notification` |
| Marketing | `AI/Marketing` |
| Meeting | `AI/Meeting` |
| Comment | `AI/Comment` |
| Travel | `AI/Travel` |
| (marker) message already processed | `AI/Done` |
| (proposal) to review before the trash | `AI/Delete` |

`AI/Done` and `AI/Delete` are deliberately single words without spaces: Gmail searches use them.

## Setup

1. In n8n: *Workflows → ⋯ → Import from file*, for each of the 4 files. On every Gmail node, select your Gmail
   credential.
2. Run **"create labels"** once (*Execute workflow*).
3. In the **"Prepare message"** nodes (sorting workflows), check the `MODEL` line: the name given by `lab main-model`.
4. Test "sort new messages" with *Execute workflow*, then activate it.
5. Activate "sort old messages" (or run it by hand): it processes 200 messages per run and stops by itself once
   everything is labelled `AI/Done`.

## Deleting the useless ones: the circuit

1. The sorting adds `AI/Delete` to the messages that look worthless. **Nothing is deleted at this stage.**
2. You open the `AI/Delete` label in Gmail and remove the label from the ones you want to keep.
3. You run "trash approved messages": the remaining messages go to Gmail's **Trash**, **recoverable for 30 days** (Gmail
   empties it afterwards). It is not a permanent deletion.

What can receive `AI/Delete`: only the **Marketing** and **Notification** categories, never a starred or important
message or one larger than 300 KB, and only if the model answers `deletable: true`. These safeguards are in the code; the
model cannot bypass them. The trash workflow refuses a batch of more than 1000 messages and ignores starred messages.

## Good to know

- **Duration:** Ollama processes one message at a time. Count a few seconds per message with the main model: 200 messages
  take about half an hour, a large mailbox several nights. As soon as the first batch has run, open the execution in n8n
  and look at the real duration.
- **VRAM:** the main model is loaded during the sorting. Deactivate the workflows during image sessions (images mode) or
  Hermes agent sessions.
- **Untrusted content:** the message text is data, with the instruction to follow no instruction it contains. The output
  is constrained by a schema (7 categories, a boolean, a reason): at worst, a wrong label.
- **Backup:** workflows and credentials are in the n8n database, covered by `lab backup`.
- **First run on old messages:** review a sample of `AI/Delete` before the first trash run, for example 30 messages
  picked at random. It is your only check of the model's quality on your mailbox.

## What is not verified

- The JSON files have **never been imported into n8n** here. The logic of the Code nodes is tested outside n8n; the
  parameters of the Gmail and HTTP nodes follow the n8n format as known when writing (n8n 2.43.8), and a field may need an
  adjustment depending on your version.
- **To watch first:** that the Gmail node accepts `TRASH` as a label (trash), that "Search old messages" returns the
  message body (`simple: false`), and that the trigger exposes `labelIds` and `internalDate`. Without `sizeEstimate`, the
  "large message" protection does not apply.
- The Ollama call (`format` as a JSON schema, `think: false`) has not been tried with every model.
- The quality of the classification and of the `deletable` field on a real mailbox is not measured.
