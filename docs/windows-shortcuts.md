# Windows shortcuts: act on AiBeast without typing a command

## The console: a window with buttons (the simplest)

Double-click **`AiBeast.bat`** (the only file at the root of the `windows\` folder, with the SSH config; everything else
is in `outils\`). A window opens with buttons, grouped by theme:

1. **Connection**: open / close the tunnels, test the connection. The state of the tunnels (open or closed) is shown at
   the top and updates by itself.
2. **Browser**: portal, button panel, ComfyUI, Open WebUI, n8n (a message tells you if the tunnels are closed).
3. **Delivery**: deploy the new version to AiBeast, copy the backups to this PC.
4. **Modes**: images, normal, agents, state, health.
5. **Maintenance**: update, backup, Hermes (projects, review, merge).

Actions that change AiBeast (deploy, update, backup) ask for a confirmation. Every long action opens in its own window,
which stays open until you press Enter: it reuses the scripts below, unchanged. The individual `.bat` files remain usable
in `outils\`.

If the console does not open, run `outils\AiBeast-Console.ps1` with right-click > Run with PowerShell and read the error.

Double-click a `.bat` file in the `windows\outils\` folder on your PC. Each shortcut connects to AiBeast over SSH (like
`Ouvrir-AiBeast.bat`), runs the matching `lab` command and shows the result. You need the network (VPN if you are away),
the SSH key and the `aibeast` shortcut in the PC's SSH configuration, generated by `lab client` on AiBeast (see
`docs/remote-access.md`). The `windows\` folder can be anywhere on the PC: the `ai-lab.tar.gz` archive and the
`aibeast-backup\` backup copy are looked for next to it.

| Shortcut | What it does | Equivalent command |
|---|---|---|
| `AiBeast-Menu.bat` | Numbered menu with all the actions below | — |
| `AiBeast-Images.bat` | Unloads the language model, starts ComfyUI, opens `http://127.0.0.1:8188` if the tunnel is up | `lab mode images` |
| `AiBeast-Normal.bat` | Stops ComfyUI, restores Kokoro and Tika | `lab mode normal` |
| `AiBeast-Agents.bat` | Frees the VRAM for Hermes | `lab mode agents` |
| `AiBeast-Sante.bat` | Full health check | `lab doctor` |
| `AiBeast-Mise-a-jour.bat` | Backup then image update, in a `tmux` session (continues if the connection drops) | `lab update` |
| `AiBeast-Hermes.bat` | Review and merge the agent's work, open Hermes in a project, create a project | `lab dev …` |

The menu adds the state (`lab mode status`), the backup (`lab backup run` under tmux) and opening the portal.

The file names keep their original (French) spelling so that existing shortcuts and habits keep working:
*Ouvrir* = open, *Fermer* = close, *Sante* = health, *Mise-a-jour* = update, *Deployer* = deploy, *Sauvegarder* = back up,
*Installer* = install, *Approuver* = approve, *Isoler* = isolate.

## Default model

No need to give `--model`: `lab bench`, `lab dev start` and `lab dev ctx64` use the **main model**, chosen in this order:
1. the `LAB_MODEL` variable (one-off);
2. the stored setting: `lab config set MODEL NAME` (`lab config list` to see it, `lab config unset MODEL` to remove it);
3. otherwise the **largest installed model**, never Open WebUI's small task model nor an embedding model.

`lab main-model` prints the current choice. **Open WebUI**'s default model is not managed here: as far as we know it is
set in its interface (Settings → Models), and an environment variable would be ignored once that setting is saved (not
verified).

## Other files in the `outils\` folder

| File | Role |
|---|---|
| `Installer-config-SSH.bat` | Installs or updates the `aibeast` shortcut in `%USERPROFILE%\.ssh\config` from `windows\ssh_config_aibeast.txt` (generated by `lab client`); backs up the old configuration, does not touch the other blocks |
| `Installer-admin-hermes.ps1`, `Approuver-script-hermes.ps1` | **On the test machine**, as administrator: let Hermes run the `.bat`/`.py` scripts you approved as administrator, without being an administrator (see `docs/hermes-ssh.md`) |
| `Isoler-machine-de-test.ps1` | To run **as administrator on the agents' test machine** (not on your PC): cuts the Internet and DNS for that machine, forbids SSH tunnels for the Hermes account; `-Undo` to revert (see `docs/agent-isolation.md`) |
| `recuperer-work-hermes.bat` | To run on the Windows test machine (`lab remote add … --windows`) with your account: copies `C:\Users\hermes\work` to `Documents\hermes-work` (robocopy, deletes nothing) |
| `Deployer-sur-AiBeast.ps1` | Delivers `ai-lab.tar.gz` (built on AiBeast by `scripts/release.sh`). Refuses if AiBeast's git repository has uncommitted changes, shows `git status` after extraction. Safety backup `~/avant-*.tgz` (≈ 1 MB: without `bench/.venv` or `bench/results`, which the delivery never touches) |

## Security of the shortcuts

- No new service on AiBeast: a shortcut is an SSH command with your key.
- The project and branch names shown by the menu come from AiBeast, so partly from the agent. `lab dev pending` only
  outputs names made of safe characters, the menu **validates them again** before putting them into a command, and the
  review strips escape sequences from the text written by the agent. Merging always runs the check again in the sandbox
  and asks you for confirmation.

## What is not verified

- Only part of the PowerShell scripts has been run on a real Windows machine (tunnels, SSH config, test machine tools).
  The logic on the AiBeast side (`lab config`, `lab main-model`, `lab dev pending/names`, hostile names) is tested by
  `scripts/test-dev.sh`; the Windows side of the menu is not covered by automated tests. On a first try, run
  `AiBeast-Sante.bat` (the simplest) and read any error.
- Interactive actions (Hermes, update under tmux): started with `Start-Process … -NoNewWindow -Wait` to keep the
  terminal; not tried.
- `lab tmux update`: if the `lab-update` session already exists, the shortcut attaches to it (not tried).
- The path `~/.local/bin/lab` assumes `lab install` was done on AiBeast (it is if `lab` works in your terminal).
